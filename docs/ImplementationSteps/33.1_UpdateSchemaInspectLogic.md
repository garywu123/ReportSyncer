# Schema Inspect Refactor Playbook（给 Low-Level AI）

## 目标

把当前“inspect 逻辑 + SchemaRole 语义混乱”的实现，重构为：

* **Source**：只做 **Existence / Minimal** 检查（表是否存在，必要时列是否存在）。**不关心 FK**。
* **Target**：做 **Full Schema**（列/类型/PK/FK/Identity 等），用于排序与写入策略。
* `SchemaRole` 只表示 **归属侧（Source/Target）**，不可变，且**由调用方显式传入**。

> 核心原则：**Side（Source/Target）** 和 **Level（Existence/Full）** 是两条独立维度。

---

## Minimal Contract（只给形状，不给大段实现）

### 1) Enums

```csharp
public enum SchemaRole
{
    Source,
    Target
}

public enum SchemaInspectionLevel
{
    ExistenceOnly,  // tables (and optionally columns) existence
    Full            // columns + pk + fk + identity + extra metadata
}
```

### 2) Request

```csharp
public sealed class SchemaInspectionRequest
{
    public required ConnectionConfig Connection { get; init; }
    public required IReadOnlyCollection<TableIdentifier> Tables { get; init; }
    public required SchemaRole Role { get; init; }
    public required SchemaInspectionLevel Level { get; init; }
}
```

### 3) Interface

```csharp
public interface ISchemaInspector
{
    Task<SchemaSnapshot> InspectAsync(SchemaInspectionRequest request, CancellationToken ct = default);
}
```

### 4) Snapshot（关键属性）

```csharp
public sealed class SchemaSnapshot
{
    public SchemaRole Role { get; }
    public SchemaInspectionLevel Level { get; }
    public IReadOnlyCollection<TableSchema> Tables { get; }
}
```

> 注意：`Level` 写进 snapshot，便于 debug 时一眼知道这份快照的“深度”。

---

## 关键设计决策

* **不拆成两个 inspector class**（例如 `SourceSchemaInspector` / `TargetSchemaInspector`）。
* **只拆成一个 inspector + 两种 Level**：`ExistenceOnly` 与 `Full`。

理由：

* 两个 inspector class 会造成 SQL 连接、缓存、日志、异常模型、DI wiring 的重复。
* 真正差异只有“查哪些 metadata”，用 `Level` 做分支更干净。
* 将来如果要做第三种 Level（例如 `ColumnsOnly`），无需增加更多 class。

## Atomic Implementation Steps（严格顺序）

### Step 0：定位修改点

1. 找到 `ISchemaInspector` 定义文件。
2. 找到 `SqlServerSchemaInspector.InspectAsync(...)`。
3. 找到所有调用 inspect 的 orchestrator / preflight 入口。
4. 找到所有相关 UT / IT。

---

### Step 1：新增 `SchemaInspectionLevel`

* 新建文件：`SchemaInspectionLevel.cs`
* 添加 enum：`ExistenceOnly`, `Full`

---

### Step 2：扩展 `SchemaInspectionRequest`

* 如果已经存在 request：新增 `Level` 属性
* 否则创建 request（包含 Connection/Tables/Role/Level）

---

### Step 3：更新 `ISchemaInspector` 签名

把旧签名替换为：

```csharp
Task<SchemaSnapshot> InspectAsync(SchemaInspectionRequest request, CancellationToken ct = default);
```

不要保留 overload（避免 Low-Level AI 走捷径引入语义不一致）。

---

### Step 4：改 `SchemaSnapshot`

1. 确保 `Role` 不可变（readonly / get-only）。
2. 新增 `Level`（同样不可变）。
3. 构造函数里保存 `Role` 与 `Level`。

---

### Step 5：重构 `SqlServerSchemaInspector.InspectAsync`

#### 5.1 参数校验

* `request` / `request.Connection` / `request.Tables` 不能为空。

#### 5.2 空表集合逻辑

* `Tables.Count == 0`：返回空 snapshot

  * `Role = request.Role`
  * `Level = request.Level`

#### 5.3 Level 分支

伪代码（只描述流程，不贴大段 SQL）：

```csharp
switch (request.Level)
{
    case SchemaInspectionLevel.ExistenceOnly:
        // Query sys.tables or INFORMATION_SCHEMA.TABLES for existence
        // Return TableSchema with minimal fields populated
        break;

    case SchemaInspectionLevel.Full:
        // Existing logic: columns + types + pk + fk + identity
        // Return full TableSchema
        break;
}
```

#### 5.4 ExistenceOnly 输出形状

* 对每个请求表：

  * 如果存在：`TableSchema` 基本信息（schema/name）
  * 如果不存在：不要偷偷忽略，应该通过上层 Preflight 抛出可读错误（见 Step 6）。

> 建议：ExistenceOnly 也可以顺手查列存在（若你的配置允许用户指定列映射/过滤），但**不要查 FK**。


---

### Step 7：更新 Mapping 使用方式

* Mapping 不应依赖 “空表 => Source / 非空 => Target” 这类推断。
* Mapping 接口层面建议直接传入：

  * `sourceSnap`
  * `targetSnap`

并且可以加 guard：

```csharp
if (sourceSnap.Role != SchemaRole.Source) throw ...;
if (targetSnap.Role != SchemaRole.Target) throw ...;
```

## 测试更新（UT + IT）

### UT-1：ExistenceOnly 保持 Role

* Given: empty tables, Role=Target, Level=ExistenceOnly
* Expect: snapshot.Role == Target

### UT-2：ExistenceOnly 不填充 FK

* Given: tables 有值，Level=ExistenceOnly
* Expect: `TableSchema.ForeignKeys` 为空或 null（按你们模型定义）

### UT-3：Full 填充 FK（已有逻辑）

* Given: tables 有值，Level=Full
* Expect: FK/PK/Columns populated（按既有断言迁移）

### IT-1：Source existence 缺表报错

* Source DB 不存在某个选中表
* Expect: 报错，message 包含表名，且标记为 Source

### IT-2：Target full schema 正常读取 FK

* Target DB 存在 FK
* Expect: targetSnap.Level == Full 且 FK 数量正确

---

## Done 标准（DoD）

* `SchemaRole` 只表示 side，不再被“tables 空不空”污染。
* inspector 支持 `ExistenceOnly` 与 `Full`。
* preflight 里明确执行 source + target 两次 inspect。
* UT/IT 全绿，并新增防回归用例：`empty tables preserves Role`。
