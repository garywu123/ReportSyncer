## 1. 背景（为什么要改）

你当前的 `SchemaMapper` 已经是强配置驱动：
- 只要 `columnMapping.mappings`（或你当前等价结构）里对某个 target column 定义了 rule，并且该 column 确实存在于 target 表中，Mapper 就会优先采用该 rule。

问题：
- 这允许用户显式映射/注入到 **Identity 列**（或其它不可插入列），即使该表没有开启 `enableIdentityInsert`。
- 结果是：**SchemaMapper 阶段不报错**，同步执行阶段才在 SQL 层炸（晚失败、难定位）。

本次改动目标：
1. 在 `SchemaMapper`（schema/preflight 阶段）新增“可插入性”校验：
   - 当 target column 为 Identity 且 mapping rule 试图写入它时，必须检查 `TableTaskConfig.EnableIdentityInsert`。
2. （建议）新增一个配置一致性校验：
   - 配置里写了 mappings key，但 target 表根本没有这个列时，不要静默忽略，至少给 warning（或 error，按你策略）。
3. 让错误码/错误信息更通用（把 `ContextInjectionParameterMissing` 这种命名从语义上拉回到“通用参数缺失”）。

## 3. 设计决策（本次只做最小闭环）

### 3.1 Identity 插入规则（必须实现）
当且仅当满足以下条件时，允许对 Identity 列生成“写入型” mapping：
- `targetCol.IsIdentity == true`
- 当前 mapping 的结果不是 Ignored（即写入：OneToOne / Constant / FromParameter / FromSource 等）
- `tableTask.EnableIdentityInsert == true`

否则：SchemaMapper 应返回一个明确错误（Fail Fast）。

### 3.2 其它不可插入列（暂不实现）
Computed/rowversion/default 等信息目前你的 schema snapshot 未必具备。不要在本任务扩大 scope。

### 3.3 Rule Key 不存在于 Target 列（建议实现为 Warning）
如果用户在 `columnMapping.mappings` 中声明了一个 target 列名，但 target 表 schema 并不存在该列：
- 建议：生成 warning（不阻断），以提示 YAML 可能写错。
- 如果你偏向严格，也可 error（但会更容易打断用户流程）。

### Step 4.2：SchemaMapper 分层处理逻辑

#### 2.1 新增辅助方法
**文件**：SchemaMapper.cs

```csharp
/// <summary>
/// Check if a column is writable based on its schema properties.
/// Returns error code if the column cannot be written to, or null if writable.
/// </summary>
private static SchemaMappingErrorCode? GetColumnWritabilityError(
    ColumnSchema targetCol, 
    MappingKind mappingKind,
    bool enableIdentityInsert)
{
    // Ignored mappings never write, always safe
    if (mappingKind == MappingKind.Ignored)
        return null;

    // Computed columns cannot be written under any circumstance
    if (targetCol.IsComputed)
        return SchemaMappingErrorCode.ComputedColumnCannotBeWritten;

    // Rowversion/timestamp columns are auto-generated
    if (targetCol.IsRowVersion)
        return SchemaMappingErrorCode.RowVersionColumnCannotBeWritten;

    // Identity columns require explicit opt-in
    if (targetCol.IsIdentity && !enableIdentityInsert)
        return SchemaMappingErrorCode.IdentityInsertNotEnabled;

    return null; // Column is writable
}
```

#### 2.2 新增错误码
**文件**：SchemaMappingErrorCode.cs

```csharp
/// <summary>
/// Mapping attempted to write to a computed column which is read-only.
/// </summary>
ComputedColumnCannotBeWritten,

/// <summary>
/// Mapping attempted to write to a rowversion/timestamp column which is auto-generated.
/// </summary>
RowVersionColumnCannotBeWritten,
```

#### 2.3 集成到 Mapper 主循环
在每个生成 `ColumnMapping` 的分支后，统一调用校验：

```csharp
// After creating any ColumnMapping (FromParameter, Const, FromSource, Automap):
var mapping = new ColumnMapping(...);

// Validate writability
var writabilityError = GetColumnWritabilityError(
    targetCol, 
    mapping.Kind, 
    tableTask.EnableIdentityInsert
);

if (writabilityError.HasValue)
{
    errors.Add(CreateError(
        writabilityError.Value, 
        sourceTableId, 
        targetTableId, 
        targetCol.Name, 
        null, 
        null
    ));
    continue; // Skip this mapping
}

columnMappings.Add(mapping);
```

    $"Target column '{column}' in table '{target}' is a rowversion/timestamp column and cannot be written to.",
