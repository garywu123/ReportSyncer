## 1. 背景（Why）

### 1.1 当前现状
- SchemaMapper.MapColumns 使用内嵌规则+验证器链，按顺序处理目标列并收集 SchemaMappingError。
- 规则包含显式 Ignore/Parameter/Const/FromSource、自动映射、额外目标忽略、缺失源列错误。
- 验证器包含类型兼容检查与可写性检查，当前逐个列累积所有验证错误。
- 规则与验证器为内部嵌套类，无法独立单测，只能通过整体 MapColumns 端到端测试。
- ColumnMappingContext 封装表/列/策略/参数等元数据，但缺少测试辅助构建器。

### 1.2 痛点/风险
- 规则/验证器不可单测，问题定位需要端到端用例，成本高（阶段：Validate/Run）。
- 新增或调整规则时，优先级顺序容易破坏，缺少独立回归（阶段：Validate）。
- 验证器收集多个错误同列，可能导致噪声，难以快速定位首要失败（阶段：Validate/Run）。

### 1.3 改造目标（必须可验证）
- Goal A：规则与验证器拆分为可注入的内部类型，允许单元测试直接实例化；验证：新增针对单个规则/验证器的测试覆盖典型成功/失败路径。
- Goal B：保留现有行为顺序与错误码，MapColumns 返回的 SchemaMappingError 集合与当前逻辑一致；验证：新增回归测试对比典型表任务的错误与映射数量。
- Non-goals：不修改配置模型、不改变 SchemaMappingResult 结构、不新增外部依赖、不引入异常抛出替代错误聚合。

## 4. 设计决策（Rules / Responsibilities）

### 4.1 职责边界
- SchemaMapper： orchestrate 表级循环、调用规则链得到 ColumnMapping、运行验证器链、聚合错误与结果。
- ColumnMappingRules 集合：仅决定“映射是什么”或“返回错误”，不做可写性/类型检查。
- ColumnMappingValidators 集合：仅检查已决策映射的类型兼容与可写性，不改变映射。

### 4.2 规则定义（避免歧义）
- Rule 1（Explicit Ignore）：If ExplicitRule.Ignore==true then Mapping=Ignored.
- Rule 2（FromParameter）：If ExplicitRule.FromParameter is set and job parameter missing then Error=JobParameterMissingForMapping; else Mapping=Constant.
- Rule 3（Const）：If ExplicitRule.Const not null then Mapping=Constant.
- Rule 4（FromSource）：If ExplicitRule.FromSource set and source column missing then Error=TargetColumnMissingInSource; else Mapping=OneToOne.
- Rule 5（Explicit Fallback Ignore）：If ExplicitRule exists but no directive matched then Mapping=Ignored.
- Rule 6（Automap）：If AutomapEnabled and no ExplicitRule and source has same name then Mapping=OneToOne.
- Rule 7（ExtraTargetAllowed）：If SchemaPolicy.AllowExtraTargetColumns and column nullable/identity/computed/rowversion and no ExplicitRule then Mapping=Ignored.
- Rule 8（MissingSource）：Always Error=TargetColumnMissingInSource when prior rules unhandled.
- Priority：Rules evaluated in listed order; first handled wins.

### 4.3 已知限制
- 类型兼容使用字符串族近似判断，未做精细长度/精度校验；本轮不扩展。
- 验证器仍然依赖 SchemaSnapshot 元数据完整性，缺失元数据场景不在本轮覆盖。

#### Step 2.1 — Per-class Unit Test Cases

Below is a concise list of unit test cases to add for each new internal class (rules, validators, helpers) introduced in Step 1. Tests are described as test method names with a one-line intent; they do not include implementation code.

##### Step 2.1.1 Rule Tests

- **ExplicitIgnoreRuleTests**
  - ExplicitIgnoreRule_ReturnsIgnored_When_ExplicitRuleIgnoreTrue: returns Handled + MappingKind.Ignored when explicit rule specifies ignore.
  - ExplicitIgnoreRule_NotHandled_When_NoExplicitRule: not handled when no explicit rule present.
  - ExplicitIgnoreRule_Prioritization_WithOtherRules: ensure rule short-circuits later rules when handled.

- **FromParameterRuleTests**
  - FromParameterRule_ReturnsError_When_ParameterMissing: returns JobParameterMissingForMapping error if parameter not provided.
  - FromParameterRule_ReturnsConstant_When_ParameterExists: returns MappingKind.Constant and uses parameter value when provided.
  - FromParameterRule_Ignored_If_ExplicitIgnorePresent: explicit ignore takes precedence over parameter mapping.

- **ConstRuleTests**
  - ConstRule_ReturnsConstant_When_ConstProvided: returns MappingKind.Constant and preserves constant value.
  - ConstRule_NotHandled_When_NoConst: not handled when explicit const is null.
  - ConstRule_Priority_Over_Automap: constant mapping wins over automap when both applicable.

- **FromSourceRuleTests**
  - FromSourceRule_ReturnsOneToOne_When_SourceExists: maps one-to-one when source column exists.
  - FromSourceRule_ReturnsError_When_SourceMissing: returns TargetColumnMissingInSource error when referenced source column absent.
  - FromSourceRule_NotHandled_When_FromSourceNotSet: not handled when no FromSource directive.

- **ExplicitFallbackIgnoreRuleTests**
  - ExplicitFallbackIgnoreRule_ReturnsIgnored_When_ExplicitRuleButNoDirective: ignored when explicit rule exists but no mapping directive.
  - ExplicitFallbackIgnoreRule_NotHandled_When_NoExplicitRule: not handled if no explicit rule present.

- **AutomapRuleTests**
  - AutomapRule_ReturnsOneToOne_When_AutomapEnabled_And_SameNameSourceExists: automap maps to same-name source when enabled.
  - AutomapRule_NotHandled_When_AutomapDisabled: not handled when automap is disabled.
  - AutomapRule_DoesNotOverride_ExplicitRule: explicit rule should prevent automap from running.

- **ExtraTargetAllowedRuleTests**
  - ExtraTargetAllowedRule_ReturnsIgnored_When_PolicyAllows_And_ColumnSafeToIgnore: returns Ignored for safe-to-ignore extra target columns.
  - ExtraTargetAllowedRule_NotHandled_When_PolicyDisallows: not handled when policy forbids extra targets.
  - ExtraTargetAllowedRule_NotApplied_When_ExplicitRuleExists: explicit rules take precedence.

- **MissingSourceRuleTests**
  - MissingSourceRule_ReturnsError_When_NoPriorRuleHandled: always returns TargetColumnMissingInSource as a final catch-all.
  
##### Step 2.1.2 Validator Tests

- **TypeCompatibilityValidatorTests**
  - TypeCompatibilityValidator_ReturnsNull_When_TypesCompatible: no error when source/target types are compatible.
  - TypeCompatibilityValidator_ReturnsError_When_TypesIncompatible: returns TargetColumnTypeIncompatible for incompatible types.
