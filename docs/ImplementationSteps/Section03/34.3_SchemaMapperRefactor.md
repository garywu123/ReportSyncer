背景与设计理由（简述给执行者理解）
•	现状：MapJob(SchemaSnapshot, SchemaSnapshot, SyncJobConfig, ConnectionConfig, ConnectionConfig, SchemaPolicyConfig) 方法长、嵌套深，阅读成本高。
•	目标：拆成若干小私有函数，用 guard 早退，主流程更线性。功能、错误码、返回结果保持不变。
涉及文件
•	必须修改：SchemaMapper.cs
•	测试关注（如有时间运行）：SchemaMapperUnitTests.cs（无需改动，作为验证参考）
逐步执行（严格按顺序，保证每步可编译）
Step 1：读取现有文件，确认上下文
•	打开 SchemaMapper.cs，熟悉 MapJob(SchemaSnapshot, SchemaSnapshot, SyncJobConfig, ConnectionConfig, ConnectionConfig, SchemaPolicyConfig) 现有流程和 CreateError(SchemaMappingErrorCode, TableIdentifier?, TableIdentifier?, string?, string?, string?)、GetColumnWritabilityError(ColumnSchema, MappingKind, bool) 的使用。
Step 2：在 SchemaMapper 类内添加私有辅助方法声明（放在类内部、现有方法下方或上方均可，保持风格一致）
•	新增方法签名（先写空实现，后填逻辑）：
•	private static bool ValidateInspectionLevel(SchemaSnapshot targetSnapshot, List<SchemaMappingError> errors);
•	private static bool TryParseTableIds(TableTask tableTask, List<SchemaMappingError> errors, out TableIdentifier sourceTableId, out TableIdentifier targetTableId);
•	private static bool TryGetTables(SchemaSnapshot sourceSnapshot, SchemaSnapshot targetSnapshot, TableIdentifier sourceTableId, TableIdentifier targetTableId, List<SchemaMappingError> errors, out TableSchema sourceTable, out TableSchema targetTable);
•	private static (List<ColumnMapping> Mappings, List<SchemaMappingError> Errors) MapColumns(TableTask tableTask, TableSchema sourceTable, TableSchema targetTable, SchemaPolicyConfig schemaPolicy);
•	private static List<SchemaMappingError> ValidatePrimaryKey(TableSchema targetTable, TableIdentifier sourceTableId, TableIdentifier targetTableId, SchemaPolicyConfig schemaPolicy);
•	引用所需类型保持 using 不变（预计无需新增 using）。
Step 3：实现 ValidateInspectionLevel
•	逻辑：检查 targetSnapshot.Level != SchemaInspectionLevel.Full 则 errors.Add(CreateError(...))，返回 false；否则返回 true。
Step 4：实现 TryParseTableIds
•	检查 tableTask?.Source 和 tableTask?.Target 非空白，否则添加 InvalidTableIdentifier 错误，返回 false。
•	尝试 Parse(string) 两个字符串，捕获异常则添加同样错误，返回 false。
•	成功时 out 赋值并返回 true。
Step 5：实现 TryGetTables
•	用 TryGetTable(TableIdentifier, out TableSchema?) 获取 source/target 表；任一失败则添加对应 SourceTableNotFound 或 TargetTableNotFound 错误，返回 false。
•	成功时 out 赋值并返回 true。
Step 6：实现 MapColumns
•	准备 Errors 列表和 columnMappings 列表。
•	构建 sourceCols、targetCols 字典与原逻辑相同（忽略 targetCols 若未用可省，但保持一致性）。
•	遍历 Columns，按原逻辑顺序：
1.	若存在 mappingRule：
•	处理 Ignore -> Constant (FromParameter/Const) -> FromSource -> fallback Ignored，同原规则。
•	写入校验调用 GetColumnWritabilityError(ColumnSchema, MappingKind, bool)，遇错误添加并 continue。
•	类型兼容检查同原逻辑。
2.	若无规则且允许自动映射：按名称匹配 source 列，类型兼容检查与写入校验同原逻辑。
3.	若允许额外目标列（nullable/identity/computed/rowversion）则添加 Ignored，否则添加 TargetColumnMissingInSource。
•	返回 (columnMappings, errors)。
Step 7：实现 ValidatePrimaryKey
•	若 RequirePrimaryKey 且 targetTable.PrimaryKeyColumns.Count == 0，添加 PrimaryKeyMissing。
•	返回错误列表（可能为空）。
Step 8：重写 MapJob(SchemaSnapshot, SchemaSnapshot, SyncJobConfig, ConnectionConfig, ConnectionConfig, SchemaPolicyConfig) 主流程为 guard 风格
•	前置空检查保留：if (sourceSnapshot == null) ...
•	创建 Errors、tableMappings 变量保留。
•	调用 if (!ValidateInspectionLevel(targetSnapshot, errors)) 早退：构造 SchemaMappingResult 并返回 Fail（沿用原消息）。
•	遍历 Tables，按以下顺序：
1.	if (!TryParseTableIds(tableTask, errors, out var sourceTableId, out var targetTableId)) continue;
2.	if (!TryGetTables(sourceSnapshot, targetSnapshot, sourceTableId, targetTableId, errors, out var sourceTable, out var targetTable)) continue;
3.	调用 var (columnMappings, columnErrors) = MapColumns(tableTask, sourceTable, targetTable, schemaPolicy); errors.AddRange(columnErrors);
4.	errors.AddRange(ValidatePrimaryKey(targetTable, sourceTableId, targetTableId, schemaPolicy));
5.	创建 TableMapping 并放入 tableMappings[targetTableId] = tableMapping;
•	末尾 success/fail 返回逻辑保持不变。
Step 9：删除/收缩 MapJob(SchemaSnapshot, SchemaSnapshot, SyncJobConfig, ConnectionConfig, ConnectionConfig, SchemaPolicyConfig) 中已内联的旧大块代码
•	确保没有重复逻辑；保持 CreateError(SchemaMappingErrorCode, TableIdentifier?, TableIdentifier?, string?, string?, string?)、GetColumnWritabilityError(ColumnSchema, MappingKind, bool) 原样存在。
