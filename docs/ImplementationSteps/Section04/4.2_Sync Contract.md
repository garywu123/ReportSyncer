
## 1. 背景（Why）

### 1.1 当前现状

* Section 4 要做 PreFlight + Orchestration，但目前缺少 **Sync 层的统一入口与返回模型**。
* 没有标准化的：

  * Job 状态（成功/失败/取消/预检失败/跳过）
  * Table 级别状态（预检失败/跳过/待执行/执行失败等）
  * PreFlight 输出（执行计划、schema/mapping 结果摘要）
* 后续实现如果没有契约，会导致：

  * Orchestrator、PreFlight、未来 TableRunner 各自发明 DTO，互相打架。

### 1.2 痛点/风险

* **接口不稳定**：实现过程中随手加字段，导致测试与 host（Console/WebApi）调用来回改。
* **错误分类漂移**：该是 SchemaMismatch 的错误，被包装成 execution error，host exit code 映射乱套。
* **可观测性断裂**：UI/Console 无法稳定展示 job/table 的状态。

### 1.3 改造目标（必须可验证）

* Goal A：定义 `ISyncOrchestrator` 与 `IPreFlightValidator` 的 **最小稳定入口**，后续实现不改签名。
* Goal B：定义 `JobResult`/`TableResult`/`PreFlightResult`/状态枚举，使 **预检与执行**都有一致输出形状。
* Non-goals：

  * 不实现任何 DB 逻辑、不写 PreFlight 执行、不写 Orchestrator 实现（那是 Task 4.3/4.4）。
  * 不引入新的第三方库。

## 4. 设计决策（Rules / Responsibilities）

### 4.1 职责边界（写死）

* `ISyncOrchestrator`：唯一“运行 job”的入口。只做生命周期编排，返回 `JobResult`。
* `IPreFlightValidator`：只做预检并返回 `PreFlightResult`（不执行 DML）。
* `Contracts/*`：纯 DTO/enum，不做 IO，不 throw domain exceptions（最多参数 guard）。

### 4.2 规则定义（避免歧义）

* Rule 1：`JobResult` / `TableResult` **不得**持有 `Exception` 实例（序列化和日志会炸）。只允许 `ErrorCode/ErrorMessage`。
* Rule 2：所有时间使用 **UTC**（字段名明确 `Utc`）。
* Rule 3：DTO 使用 `record` + `init`/构造器，暴露 `IReadOnlyList<>`，禁止可变 list 外泄。
* Rule 4：`DryRun` 必须在 `PreFlightResult` 和 `JobResult` 中都可见（UI/Console 需要）。

### 4.3 已知限制

* Table 标识目前先用 `string TargetTable`（例如 `"dbo.Customer"`）。等 Schema 层 `TableIdentifier` 完全统一后再换，不在本任务扩 scope。

### Step 6 — 添加防御性拷贝（Defensive Copy）

**目标**

* 确保 DTO 中的集合字段完全不可变，外部修改不影响 DTO 内部状态。
* 实现 Rule 3 中「禁止可变 list 外泄」的要求。

**修改文件**

* `ReportSyncer.Core/Sync/Contracts/JobResult.cs`
* `ReportSyncer.Core/Sync/Contracts/PreFlightResult.cs`

**实施要点**

1. 将 `record` 主构造器改为显式构造器 + `init` 属性。
2. 在构造器中对集合参数调用 `.ToArray()` 进行防御性拷贝。
3. 确保 `IReadOnlyList<>` 类型的属性返回的是不可变副本。

**JobResult 示例**：
```csharp
public sealed record JobResult
{
    public string JobName { get; init; }
    public JobStatus Status { get; init; }
    public bool DryRun { get; init; }
    public DateTimeOffset StartedAtUtc { get; init; }
    public DateTimeOffset? FinishedAtUtc { get; init; }
    public IReadOnlyList<TableResult> Tables { get; init; }
    public string? ErrorCode { get; init; }
    public string? ErrorMessage { get; init; }

    public JobResult(
        string JobName,
        JobStatus Status,
        bool DryRun,
        DateTimeOffset StartedAtUtc,
        DateTimeOffset? FinishedAtUtc,
        IReadOnlyList<TableResult> Tables,
        string? ErrorCode = null,
        string? ErrorMessage = null)
    {
        this.JobName = JobName;
        this.Status = Status;
        this.DryRun = DryRun;
        this.StartedAtUtc = StartedAtUtc;
        this.FinishedAtUtc = FinishedAtUtc;
        this.Tables = Tables.ToArray(); // 防御性拷贝
        this.ErrorCode = ErrorCode;
        this.ErrorMessage = ErrorMessage;
    }
}
```

**PreFlightResult 示例**：
```csharp
public sealed record PreFlightResult
{
    public string JobName { get; init; }
    public bool DryRun { get; init; }
    public ExecutionPlan ExecutionPlan { get; init; }
    public IReadOnlyList<TableResult> PlannedTables { get; init; }
    public IReadOnlyList<string> Warnings { get; init; }

    public PreFlightResult(
        string JobName,
        bool DryRun,
        ExecutionPlan ExecutionPlan,
        IReadOnlyList<TableResult> PlannedTables,
        IReadOnlyList<string> Warnings)
    {
        this.JobName = JobName;
        this.DryRun = DryRun;
        this.ExecutionPlan = ExecutionPlan;
        this.PlannedTables = PlannedTables.ToArray(); // 防御性拷贝
        this.Warnings = Warnings.ToArray(); // 防御性拷贝
    }
}
```

**验收标准**

* `dotnet build` 通过。
* 外部代码传入 `List<>` 并修改后，DTO 内部集合不受影响（通过测试验证）。

## 8. Executor 注意事项（防写歪）

* 不要在 DTO 里塞 `Exception`、`StackTrace`、`InnerException` 之类的“爽字段”。后面序列化、日志、UI 都会被你拖下水。
* 不要把 `DateTime.Now` 写进 DTO 构造默认值里（测试会变随机）。时间由 orchestrator 注入。
* 不要为了“方便”把 `ExecutionPlan` 改成 `object` 或 `dynamic`。那是走向混乱的捷径。
* 代码与注释必须英文；这里的说明是中文没关系。
