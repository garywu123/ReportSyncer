
# Task 4.1 — Schema Facade：`ISchemaService / SchemaService`

> **交付对象**：低上下文、低推理能力的 GPT-5.1 mini
> **目标**：把 *Schema Inspection + Mapping + Dependency Planning* 串成一个**可复用、可测试、可阻断执行的 Facade**
> **注意**：本 Task **不执行任何 DML**，只做分析与计划

---

## 1. 背景（Why）

### 1.1 当前现状（基于你的 repo 与 Section 3）

* 已存在：

  * `ISchemaInspector` / `SqlServerSchemaInspector`
  * `SchemaSnapshot / TableSchema / ColumnSchema / ForeignKeySchema`
  * `ISchemaMapper` / `SchemaMapper`
* 尚不存在但 **Section 4 必须用到**：

  * 一个统一入口来：

    * 对一个 **SyncJob**
    * 同时完成 **Schema Inspect + Mapping + Dependency Plan**
* 当前问题：

  * PreFlight 层没法“只调用一个东西就知道 schema 是否 OK”
  * Dependency Resolver 没地方自然接入

### 1.2 痛点 / 风险

* 没有 Facade：

  * PreFlight 会变成一坨 if/else + service 调用
  * 单测很难写，逻辑散落
* Schema / Dependency / Mapping 的失败方式不统一：

  * 有的 throw
  * 有的 return Result
  * 调用方会疯

### 1.3 改造目标（必须可验证）

* **Goal A**：一个方法即可分析 *一个 SyncJob 的 schema 可执行性*
* **Goal B**：任何一步失败 → 返回 `Result.Fail`，不 throw
* **Goal C**：成功时返回一个结构化结果，供 PreFlight 使用

**Non-goals**

* ❌ 不做 Delete / Insert
* ❌ 不做权限 / safety / row count
* ❌ 不在这里决定 dry-run 行为

## 3. 行为定义（硬规则）

### Rule 1 — 输入约束

* `job.Tables` **只处理 enabled 的 TableTask**
* Dependency 只基于 **Target tables**

### Rule 2 — Inspect 策略

* Source：

  * 只 inspect job 用到的 source tables
  * inspection level 用你 repo 里已有的 *最低可 mapping level*
* Target：

  * 必须 Full inspection（FK + PK）

### Rule 3 — 调用顺序（不可调整）

```
Inspect Source
→ Inspect Target
→ SchemaMapper.Map(...)
→ DependencyResolver.BuildExecutionPlan(...)
```

### Rule 4 — 错误策略（非常重要）

* **本 Service 绝不 throw**
* 任一步失败 → `Result.Fail(...)`
* Error message 必须至少包含：

  * Job name
  * 表名（如果有）

## 4. Atomic Step-by-Step Implementation

> 每一步 **必须能编译 + 单测可跑**

---

### Step 1 — 定义 Facade 接口与返回模型

**目标**

* 建立稳定 contract，供 PreFlight 调用

**修改文件**

* `ISchemaService.cs`
* `SchemaAnalysisResult.cs`

**实施要点**

1. `ISchemaService.AnalyzeJobAsync(...)`：

   * 不暴露 inspector / mapper / resolver
2. `SchemaAnalysisResult`：

   * 只做 data container
   * 不放任何行为

**验收标准**

* 项目可编译
* 无业务逻辑

---

### Step 2 — 实现 `SchemaService` 骨架（不写逻辑）

**目标**

* 把依赖注入接好

**修改文件**

* `SchemaService.cs`

**实施要点**

1. 构造函数注入：

   * `ISchemaInspector`
   * `ISchemaMapper`
   * `IDependencyResolver`
2. 方法体先 `throw new NotImplementedException()`

**验收标准**

* DI 可解析
* 编译通过

---

### Step 3 — 提取 Job 参与的表集合

**目标**

* 明确 schema inspect 与 dependency 的输入集合

**实施要点**

1. 从 `job.Tables`：

   * 过滤 `Enabled == true`
2. 构建两个集合：

   * `sourceTables : List<TableIdentifier>`
   * `targetTables : List<TableIdentifier>`
3. **如果 targetTables 为空 → Result.Fail**

**错误信息（英文）**

```
"No enabled table tasks found for job '{JobName}'."
```

---

### Step 4 — 调用 Source Schema Inspector

**目标**

* 获取 Source Snapshot

**实施要点**

1. 调用 `ISchemaInspector.InspectAsync(...)`
2. 捕获任何异常：

   * 转成 `Result.Fail("Source schema inspection failed: ...")`

**验收标准**

* inspector 抛异常不会炸掉 service

---

### Step 5 — 调用 Target Schema Inspector

**目标**

* 获取完整 Target Snapshot（含 FK）

**实施要点**

1. Inspection level = Full
2. 同 Step 4 的错误处理方式

---

### Step 6 — 调用 SchemaMapper

**目标**

* 得到 source → target 的列映射与 context column 结果

**实施要点**

1. 调用 mapper
2. 如果 `mappingResult.IsFailure`：

   * 直接 `Result.Fail(mappingResult.Errors)`

**注意**

* **不在这里 reinterpret error**
* 原样透传

---

### Step 7 — 调用 DependencyResolver

**目标**

* 构建 Insert / Delete 顺序
* 检测 missing parent tables

**实施要点**

1. 调用：

   ```csharp
   BuildExecutionPlan(targetSnapshot, targetTables)
   ```
2. Fail 时：

   * `Result.Fail(dependencyErrors)`

---

### Step 8 — 组装 `SchemaAnalysisResult`

**目标**

* 返回完整、可执行的 schema 计划

**实施要点**

1. new `SchemaAnalysisResult(...)`
2. `return Result.Ok(result)`

### 5. **添加AAA注释和测试意图说明**

```csharp
[Fact]
public async Task AnalyzeJobAsync_WithNoEnabledTables_ReturnsFailure()
{
    // Arrange: Job with all tables disabled
    var job = CreateJob("job1", "src", "tgt", 
        Table("dbo.S", "dbo.T", enabled: false));
    var cfg = CreateConfig(new[] { Conn("src"), Conn("tgt") }, new[] { job });
    var svc = new SchemaService(new FakeInspector(), new FakeMapper(), new FakeResolver());

    // Act
    var result = await svc.AnalyzeJobAsync(cfg, job, CancellationToken.None);

    // Assert: Should fail with specific error message

    result.Error.Should().Contain("No enabled table tasks found")
        .And.Contain(job.Name);
}
```
