# Task 4.3 — PreFlightValidator Step-by-Step Playbook

## 1. 背景（Why）

### 1.1 当前现状

* Section 4 的目标是先把 **PreFlight Gate** 做实：任何 schema/mapping/dependency 失败都必须阻断后续执行。
* 当前 Task 4.3 只要求实现 `PreFlightValidator`：

  * 依赖 `ISchemaService`（Task 4.1）来做 schema 分析与 execution plan 生成。
  * PreFlight 只负责 **检查 + 产出 PreFlightResult**，不做任何 DML。
* `SchemaService.AnalyzeJobAsync(...)` 设计为 **返回 `Result<T>`**，失败时不 throw（throw 由 PreFlight 统一翻译）。

### 1.2 痛点/风险

* 如果 schema/mapping/dependency 失败没有被统一拦截，你的 orchestrator 会在后续阶段“假装能跑”，然后在执行层炸成一团难以诊断的异常。
* 错误如果不带 job/table/原因，用户只能靠猜，系统就会变成“靠运气配置同步”。

### 1.3 改造目标（必须可验证）

* Goal A：`SchemaService` 返回 Fail 时，`PreFlightValidator` 必须抛出 `SchemaMismatchException`，并包含 job name + 至少一个失败原因（英文 message）。
* Goal B：`PreFlightResult` 必须包含 `ExecutionPlan`（以及 schema/mapping 的分析结果）用于后续 orchestrator planning。
* Goal C：`dryRun` 只作为 flag 透传到 `PreFlightResult`，不在这里做“跳过执行”的决策。

Non-goals：

* 不实现 permissions/safety/work-estimation（这些是后续任务，不要偷跑 scope）。
* 不做任何 delete/insert（执行引擎属于 Section 5）。

## 4. 设计决策（Rules / Responsibilities）

### 4.1 职责边界（写死）

* `SchemaService`：负责“拿 schema、做 mapping、做 dependency planning”，以 `Result<T>` 形式返回成功/失败。
* `PreFlightValidator`：负责“把 SchemaService 的 Fail 翻译成域异常（`SchemaMismatchException`）”，并产出 `PreFlightResult`。
* `PreFlightValidator` **不得**做任何数据库写操作。

### 4.2 规则定义（避免歧义）

* Rule 1：`AnalyzeJobAsync(...)` 返回 `Result.Fail`
  → `PreFlightValidator` **必须** `throw new SchemaMismatchException(...)`
  → message 必须包含：

  * job name
  * 至少一个失败原因（mapping errors / dependency errors）
* Rule 2：`effectiveConfig.Run.DryRun == true`
  → `PreFlightResult.DryRun = true`
  → PreFlight 不做“跳过执行”的决策。
* Rule 3：`SchemaService` 如果抛出非域异常（比如 DB 连接炸了）
  → `PreFlightValidator` 允许直接透传（如果你架构要求），或 wrap 成 `SyncExecutionException`（更推荐），但**不要** wrap 成 `SchemaMismatchException`。

## 5. Atomic Step-by-Step Implementation（How）

> 每步要求：**编译通过 + 相关单测通过**。
> 一步只做一件事，别手贱把 Section 5 的执行引擎也塞进来。

---

### Step 1 — 确保 `PreFlightResult` 合同存在且最小可用

**目标**

* 确保有一个稳定的 `PreFlightResult`，可被 orchestrator 消费。
* 只承载 PreFlight 的产物，不夹带执行期结果。

**修改文件**

* `ReportSyncer.Core/Sync/Contracts/PreFlightResult.cs`（如已存在则只核对字段）

**实施要点**

1. 定义为 `sealed record` 或 `record`（按你项目风格），不可变。
2. 最小字段建议：

   * `JobName: string`
   * `DryRun: bool`
   * `Schema: SchemaAnalysisResult`
3. 不要加入 permissions/safety/estimate 等字段（本 Task 不做）。

**验收标准**

* `ReportSyncer.Core` 能编译通过。
* 没有引入对 Host 项目的引用。

---

### Step 2 — 实现 `PreFlightValidator` 主流程

**目标**

* 调用 `ISchemaService.AnalyzeJobAsync`
* 成功则返回 `PreFlightResult`
* 失败则抛 `SchemaMismatchException`（信息可行动）

**修改文件**

* `ReportSyncer.Core/Sync/PreFlightValidator.cs`

**实施要点**

1. 构造函数依赖（Constructor injection）：

   * `ISchemaService schemaService`
   * （可选但推荐）`ILogService log`
2. 实现 `ValidateAsync(effectiveConfig, job, ct)`：

   * `ct.ThrowIfCancellationRequested();`
   * `var analysisResult = await _schemaService.AnalyzeJobAsync(effectiveConfig, job, ct);`
   * `if (analysisResult.IsSuccess)`：

     * `return new PreFlightResult(job.Name, effectiveConfig.Run.DryRun, analysisResult.Value);`
   * `else`：

     * 把 `analysisResult.Error`（或 errors 集合）整理成 **英文** message
     * `throw new SchemaMismatchException(message);`
3. message 组装硬要求（英文）：

   * 必须包含：`Job='<jobName>' preflight failed.`
   * 以及至少一条 reason（例如：`Reason: Missing dependency table 'dbo.Parent' required by 'dbo.Child'.`）
4. 不要在 PreFlight 内部做“多表聚合检查”，那是 SchemaService 的职责。

**验收标准**

* Unit tests 可稳定断言：Fail → 抛 `SchemaMismatchException`，且 message 包含 job name 与原因关键词。
* 成功时返回的 `PreFlightResult.Schema.ExecutionPlan` 不为 null。

---

### Step 3 — 加入最小日志（可选但推荐）

**目标**

* 不要让诊断完全靠异常文本。
* 但也别搞成“日志驱动的业务逻辑”。

**修改文件**

* `ReportSyncer.Core/Sync/PreFlightValidator.cs`

**实施要点**

1. 成功：

   * `log.LogInformation("Preflight passed for job {JobName}.", job.Name);`
2. 失败：

   * `log.LogError("Preflight failed for job {JobName}: {Reason}", job.Name, reasonSummary);`
3. 日志消息必须英文，结构化参数必须存在（`{JobName}`）。

**验收标准**

* 单测不需要验证日志内容（除非你已有统一日志测试风格）。

### 6.1 新增/更新单测清单（Unit）

文件：`ReportSyncer.Tests/Unit/Sync/PreFlightValidatorTests.cs`

> 用 `Moq` mock `ISchemaService`，不要碰 DB。

#### Test 1：SchemaService Fail → 抛 SchemaMismatchException

* Arrange：

  * mock `AnalyzeJobAsync` 返回 `Result.Fail(...)`（错误内容里放一个可识别 reason，比如 `"Missing dependency: dbo.Parent"`）

## 7. Executor 注意事项（防写歪）

* 不要在 `PreFlightValidator` 里实现 permissions/safety/work estimation（那是别的 Task）。
* 不要在 `PreFlightValidator` 里做任何 DML（哪怕是“试探性 delete”也不行）。
* `SchemaService` Fail 才是 `SchemaMismatchException`，不要把 DB 连接失败也硬塞进 schema mismatch（那应该是 `SyncExecutionException` 或原样透传，按你异常体系定）。
* 异常 message、日志 message 一律英文。
* 不要引入新依赖包；只用现有 `xUnit/Moq/FluentAssertions`。
