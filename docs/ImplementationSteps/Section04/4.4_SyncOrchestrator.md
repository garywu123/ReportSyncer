# Task 4.4 Step-by-Step Playbook — SyncOrchestrator（Load → Resolve Job → PreFlight → 返回结果）

> 交付对象：Junior Executor AI（低上下文、按步骤机械执行）
>
> 目标：实现 `SyncOrchestrator` 的最小闭环入口，只负责 **加载配置 → 找到 job → 跑 preflight → 在 dry-run 下返回结果**。  
> 注意：这一步**不做任何 DML**，非 dry-run 必须明确报错“还没实现执行引擎”。

---

## 1. 背景（Why）

### 1.1 当前现状
- Section 4 已经把“schema/mapping/dependency 的检查能力”逐步补齐（Task 4.0~4.3）。
- `IPreFlightValidator` 已存在（Task 4.3），负责做检查并产出 `PreFlightResult`（或抛异常）。
- `IConfigurationProvider` 已存在，负责 `LoadAndValidateAsync(configPath, overrides, ct)` 得到 **effective config**（已合并 runtime overrides）。
- 现在缺一个 **后端入口编排器**：把这些东西串起来，形成可测试的生命周期。

### 1.2 痛点/风险
- 没有 Orchestrator：Host 层（Console/WebApi）无法有稳定入口调用、也无法用单测锁定“调用顺序”和“dry-run 行为”。
- 若 Orchestrator 吞异常：preflight gate 会变成“看起来没问题但其实失败了”的灾难。
- 若 Orchestrator 在非 dry-run 静默继续：会引入未实现的执行引擎路径，产生“半拉子同步”的误导行为。

### 1.3 改造目标（必须可验证）
- Goal A：实现 `ISyncOrchestrator.RunJobAsync(string configPath, string jobName, RuntimeOverrides? overrides, CancellationToken ct)` 的真实编排逻辑（可单测验证调用顺序）。
- Goal B：dry-run 时返回 `JobResult`，并且每张表都标记为 `Skipped_DryRun`（或等价状态）。
- Goal C：preflight 抛任何异常时，Orchestrator **不吞**，直接冒泡（可单测验证）。
- Non-goals：
  - 不做 Delete/Insert/执行引擎（Section 5 才做）。
  - 不做权限/安全/估算（你现在也没实现，别硬塞）。

## 3. 行为变化（User-facing / API）

### 3.1 行为（硬规则）

* 必须先加载配置，再 resolve job，再跑 preflight：

  * `LoadAndValidateAsync(configPath, overrides, ct)`
  * resolve job
  * `PreFlightValidator.ValidateAsync(effectiveConfig, job, ct)`
* PreFlight 抛任何异常：Orchestrator 不捕获、不包装、不吞，直接抛出。
* dry-run：返回 `JobResult`，每张表标记为 `Skipped_DryRun`（或等价状态）。
* 非 dry-run：在完成 preflight 后，抛 `SyncExecutionException("Execution engine not implemented. Implement Section 5.")`。

### 3.2 兼容性说明

* 纯新增 `SyncOrchestrator`，不改接口契约；对外兼容性 OK。

## 4. 设计决策（Rules / Responsibilities）

### 4.1 职责边界（写死）

* `SyncOrchestrator`：只负责 **编排**。它不做 schema 逻辑、不做依赖图、不做 SQL、不做执行。
* `IConfigurationProvider`：负责得到 effective config（含 overrides 的合并）。
* `IPreFlightValidator`：负责检查 + 产出 `PreFlightResult`（或抛异常）。
* `JobResult/TableResult`：只做“结果载体”，不做业务决策。

### 4.2 规则定义（避免歧义）

* Rule 1：`RunJobAsync` 必须按顺序调用：Load → Resolve Job → PreFlight。
* Rule 2：`PreFlight` 抛异常 → 直接冒泡（不要 `try/catch`）
* Rule 3：`effectiveConfig` 的 dry-run flag 为 true → 返回 `JobResult`，所有表为 `Skipped_DryRun`。
* Rule 4：dry-run flag 为 false → 抛 `SyncExecutionException("Execution engine not implemented. Implement Section 5.")`。

### Step 2 — 实现 `RunJobAsync` 的调用顺序（Load → Resolve Job → PreFlight）

**目标**

* 严格实现调用顺序（Rule 1）
* 正确传递 `ct` 和 `overrides`
* Preflight 的异常不处理（Rule 2）

**修改文件**

* `ReportSyncer.Core/Sync/SyncOrchestrator.cs`

**实施要点**

1. 写入方法签名（必须完全匹配接口）：

   ```csharp
   public async Task<JobResult> RunJobAsync(
       string configPath,
       string jobName,
       RuntimeOverrides? overrides,
       CancellationToken ct)
   ```
2. 参数校验（英文 message）：

   * `configPath` / `jobName` 不能为空或空白。
3. 调用配置加载（必须第一个）：

   ```csharp
   var effectiveConfig = await _configurationProvider
       .LoadAndValidateAsync(configPath, overrides, ct)
       .ConfigureAwait(false);
   ```
4. Resolve job：

   * 从 `effectiveConfig` 中找到 `SyncJobConfig`（按你的类型定义来）
   * 匹配规则：优先 `OrdinalIgnoreCase`
   * 找不到：抛你 repo 里现有的配置异常类型（优先 `ConfigurationException`），message 必须包含 jobName。
   * 例（按需改类型名）：

     ```csharp
     throw new ConfigurationException($"Job '{jobName}' was not found in configuration.");
     ```
5. 调用 preflight（必须在 resolve 之后）：

   ```csharp
   var preFlight = await _preFlightValidator
       .ValidateAsync(effectiveConfig, job, ct)
       .ConfigureAwait(false);
   ```
6. **不要 try/catch**。preflight 抛什么，你就让它抛出去。

**验收标准**

* 编译通过（此时可以先临时返回一个 `throw new NotImplementedException()`，因为下一步才拼 `JobResult`）。
* 新增单测（Step 3）可以验证调用顺序。

### Step 3 — 单测：验证调用顺序与异常冒泡

**目标**

* 锁定 Orchestrator 生命周期（Rule 1 / Rule 2）

**修改文件**

* `Tests/ReportSyncer.Core.Tests/Sync/SyncOrchestratorTests.cs`

**实施要点**

1. 测试 `SyncOrchestrator_LoadsConfig_ResolvesJob_ThenCallsPreFlight`

   * Arrange：

     * `Mock<IConfigurationProvider>`：`LoadAndValidateAsync` 返回一个包含目标 job 的 `SyncConfiguration`
     * `Mock<IPreFlightValidator>`：`ValidateAsync` 返回一个 `PreFlightResult`
     * 用 `MockSequence` 验证调用顺序：

       * 先 `LoadAndValidateAsync`
       * 再 `ValidateAsync`
   * Act：调用 `RunJobAsync(configPath, jobName, overrides, ct)`
   * Assert：

     * 两个 mock 被调用一次
     * `ValidateAsync` 的 job 参数就是你 resolve 的那个 job（引用相等或关键字段相等）

3. 所有测试中的异常 message 用英文。

**验收标准**

  * preflight 异常不被吞

### Step 4 — 实现 dry-run 分支：返回 `JobResult` 且所有表为 `Skipped_DryRun`

**目标**

* 满足 Rule 3：dry-run 返回结构化结果
* 每张表的状态为 `Skipped_DryRun`（或等价）

**修改文件**

* `ReportSyncer.Core/Sync/SyncOrchestrator.cs`
* `Tests/ReportSyncer.Core.Tests/Sync/SyncOrchestratorTests.cs`

**实施要点**

1. 从 `effectiveConfig` 读取 dry-run flag：

   * 优先：`effectiveConfig.RunConfig.DryRun`（按你的实际字段名）
2. 如果 dry-run 为 true：

   * 构造 `JobResult`
   * 表清单来源：从 `job` 里拿“参与的 tables”（例如 `job.TableTasks` / `job.Tables`，按你实际定义）
   * 为每张表构造 `TableResult`：

     * `TableName = ...`
     * `Status = TableStatus.Skipped_DryRun`（或等价）
   * `JobResult` 的状态也应表达 dry-run（例如 `JobStatus.Skipped_DryRun` 或 `Completed_DryRun`，按你已有枚举）
   * 如果 `JobResult` 有字段能塞 `PreFlightResult`（例如 `PreFlight` / `Plan`），就把 `preFlight` 放进去；没有就别硬加字段。
3. 新增单测 `SyncOrchestrator_WhenDryRun_ReturnsJobResultWithSkippedTables`

   * Arrange：配置里 dry-run = true，job 含 2~3 张表
   * Act：调用 `RunJobAsync`
   * Assert：

     * `result` 不为 null
     * `result.Tables.Count == jobTables.Count`
     * 每个 `TableResult.Status == Skipped_DryRun`
     * `preFlightValidator.ValidateAsync` 被调用一次

**验收标准**

* 单测通过：dry-run 分支输出稳定。

### Step 5 — 实现非 dry-run 分支：抛 `SyncExecutionException`

**目标**

* 满足 Rule 4：非 dry-run 必须明确报错
* 注意 Rule 1：依然要先 preflight，再决定执行分支

**修改文件**

* `ReportSyncer.Core/Sync/SyncOrchestrator.cs`
* （如需）新增异常类型文件：`ReportSyncer.Core/Sync/Exceptions/SyncExecutionException.cs`
* `Tests/ReportSyncer.Core.Tests/Sync/SyncOrchestratorTests.cs`

**实施要点**

1. 当 dry-run 为 false：

   * 在 preflight 成功返回后，直接：

     ```csharp
     throw new SyncExecutionException("Execution engine not implemented. Implement Section 5.");
     ```
2. 如果 repo 里没有 `SyncExecutionException`：

   * 新建一个最小异常类：

     ```csharp
     namespace ReportSyncer.Core.Sync.Exceptions;

     public sealed class SyncExecutionException : Exception
     {
         public SyncExecutionException(string message) : base(message) { }
     }
     ```
   * message 必须英文、且精确匹配测试断言。
3. 新增单测 `SyncOrchestrator_WhenNotDryRun_ThrowsSyncExecutionException`

   * Arrange：dry-run = false，preflight 返回成功结果
   * Act + Assert：抛 `SyncExecutionException` 且 message 匹配
   * 额外 Assert：`ValidateAsync` 仍然被调用（证明 preflight gate 仍然生效）

**验收标准**

* 单测通过：非 dry-run 行为固定为“明确失败”。
